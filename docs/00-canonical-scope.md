# Canonical Scope

## Mission

Build a reproducible system for reconstructing platform capabilities from legally reusable open-source components and clean-room implementations.

## First research boundary

Inventory and assess public repositories connected to:

- Block
- Square
- Square Developers
- Cash App
- Weebly
- Afterpay
- TIDAL
- Proto
- Spiral
- c equals

The list contains companies, product brands, developer organizations, and research initiatives. They must remain correctly classified rather than flattened into one organization.

## What this repository may contain

- links and metadata for upstream repositories;
- license and NOTICE evidence;
- architecture and dependency analysis;
- documented local test results;
- independent adapters and compatibility contracts;
- clean-room specifications;
- approved forks or vendored source where policy permits;
- implementation plans for Amarax and Daycostra modules.

## What this repository must not become

- an unreviewed bulk mirror;
- a place to remove attribution;
- a counterfeit Block or Square product;
- a store for credentials, production data, private source, or leaked material;
- an assumption that rebranding overrides license obligations;
- a financial-service deployment plan without regulatory review.

## Definition of success

A reviewer can answer, for every candidate repository:

1. What capability does it provide?
2. Is it genuinely reusable and under which license?
3. Can it run independently from private upstream infrastructure?
4. What security and maintenance risk does it introduce?
5. Where does it fit in the Amarax or Daycostra architecture?
6. Should it be adopted, forked, referenced, or rejected?
7. What exact work is needed to make the decision executable?
