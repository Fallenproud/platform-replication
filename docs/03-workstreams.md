# Workstreams

## WS-00 Program governance

Own canonical scope, decision quality, naming, evidence standards, and release gates.

## WS-01 Organization and repository discovery

Enumerate public organizations and repositories, remove duplicates, identify moved or archived projects, and preserve canonical upstream locations.

## WS-02 License and provenance

Classify licenses, NOTICE requirements, dependency obligations, assets, datasets, models, and trademark boundaries.

## WS-03 Build and self-hostability

Reproduce builds, document runtime dependencies, identify private service coupling, and produce minimal local deployment instructions.

## WS-04 Architecture reconstruction

Create component, data-flow, event, permission, and deployment diagrams without copying unsupported assumptions.

## WS-05 Security and supply chain

Review secrets, dependency vulnerabilities, update mechanisms, telemetry, sandboxing, permissions, and destructive operations.

## WS-06 Product fit and target mapping

Map candidates to Amarax Central, AIKO, AIKOV, Daycostra, Voltino, SnapForge, Amarax Nexus, or a distinct product extension explicitly approved for the capability.

## WS-07 Fork and adapter engineering

Create governed forks, compatibility adapters, upstream sync procedures, patch queues, and local release pipelines for approved components.

## WS-08 Clean-room reimplementation

Turn reference-only projects into behavioral specifications, contracts, test vectors, and independent implementations.

## WS-09 Integration and qualification

Run contract, security, performance, recovery, observability, and licensing checks before a component is admitted to a production product.

## WS-10 Documentation and reusable skill

Maintain the assessment skill, templates, catalogs, decision records, and handoff packages.
