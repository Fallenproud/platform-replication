# Master Roadmap

## Phase 0 — Bootstrap

- establish repository structure;
- establish four-way disposition model;
- establish license policy;
- establish assessment schema and issue template;
- seed organization and repository catalogs.

Exit: the program can accept a repository without inventing a new process.

## Phase 1 — Block ecosystem inventory

- enumerate organizations and canonical repositories;
- detect moved, renamed, duplicated, and archived projects;
- collect license and activity evidence;
- assign initial capability domains.

Exit: prioritized inventory with no unclassified high-value candidate.

## Phase 2 — Priority audits

Initial priority set:

1. `aaif-goose/goose` — agent runtime and extensibility.
2. `block/thread-manager-for-amp` — multi-thread/session control reference.
3. `block/agent-task-queue` — agent work scheduling.
4. `block/ai-rules` — agent policy and instruction management.
5. `block/xcode-index-mcp` — MCP and code-index integration.
6. `block/proto-fleet` — operational control-plane study.
7. selected Square libraries — mature SDK and library engineering patterns.
8. Weebly public components — theme and website-builder extension patterns.

Exit: decision records and executable work packages for every priority candidate.

## Phase 3 — Controlled prototypes

Build isolated proofs of concept. No direct production merge. Compare upstream adoption against clean-room replacement.

Exit: measured evidence for integration cost, performance, security, and independence.

## Phase 4 — Product admission

Admit approved components into their target repositories through normal pull requests, third-party notices, security review, and release qualification.

## Phase 5 — Ecosystem reconstruction

Only after component qualification, compose higher-level capabilities such as agent operations, developer platform, website generation, commerce-adjacent workflows, media tooling, or fleet control. Regulated financial operations remain a separate program.
